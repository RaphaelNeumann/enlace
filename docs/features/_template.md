# <Feature name>

## Goal

1-2 sentences. Which user problem this solves and for whom.

## In scope / out of scope

- **IN**: list of what the first version includes.
- **OUT**: list of what is deferred (and why), so reviewers know what was deliberately skipped.

## UX flow

Step-by-step from the user's perspective. Behavior, not visual mockups.

## Data model

New tables, columns, enums, and relationships introduced by this feature. Skip if the feature is purely presentational.

## Permissions

Public viewer / `COUPLE` / `CEREMONIAL` — who can see what, who can do what.

## Open decisions

Numbered list of things that must be decided before the feature can be implemented.

## Implementation notes

Concrete technical pointers: Server Action paths, Zod schemas, CSP changes, new env vars, library choices, edge cases. Skip if obvious.
